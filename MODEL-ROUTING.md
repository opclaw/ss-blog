# Маршрутизация моделей: какая модель на какую задачу

> **Статус файла.** Оригинал потерялся при переносе репозитория — в истории git его нет
> (`git log --all -- MODEL-ROUTING.md` пуст). Восстановлен 2026-10-05 по записи-ориентиру
> из `CLAUDE.md` (раздел 4, «В начале каждой сессии», п. 3). Правила ниже — те, что были
> зафиксированы там; свежих слепых тестов с момента утраты файла не проводилось, поэтому
> формулировки помечены: что подтверждено, а что требует перепроверки.

## Правила

| Задача | Модель | Обоснование |
|---|---|---|
| Черновики статей | **k2.7 / Ollama** | локально, быстро, дешево; текст всё равно идёт на редактуру |
| Дизайн-черновики | **DeepSeek Pro** | выбрана по итогам слепого теста |
| Редактура, схемы, приёмка | **старшая модель** | здесь ошибка дороже всего: факты, цифры, логика |

## Что подтверждено, а что нет

- **Подтверждено:** выбор DeepSeek Pro для дизайн-черновиков сделан по итогам слепого теста —
  это зафиксировано в `CLAUDE.md`.
- **Подтверждено практикой:** редактуру, схемы и приёмку ведёт старшая модель — этим правилом
  проект пользуется постоянно (правки арифметики в статьях, проверка фактов, аудит сборки).
- **Требует перепроверки:** связка k2.7/Ollama для черновиков — она указана как ориентир,
  но слепых тестов на текстах в репозитории нет. Если черновики перестанут устраивать по
  качеству, первым делом стоит пересмотреть именно эту строку, а не остальные.

## Как менять

1. Любое изменение правила — через слепой тест: один и тот же вход, несколько моделей,
   оценка вслепую, без знания, кто есть кто.
2. Результат теста записывать сюда же: дата, вход, участники, кто победил и по какому
   критерию. Правило без записанного теста считается временным.
3. Удалять правило нельзя — только заменять новым с пометкой, чем оно лучше прежнего.
