# Wordstat: семантика блога

Данные собраны через Yandex Cloud Search API v2 (`topRequests`), регион — Россия, период — 30 дней.

| Файл | Что внутри |
|---|---|
| `THEMING.md` | тематика: 14 кластеров, 185 запросов, ~866 619 показов/мес, приоритеты и логика распределения по статьям |
| `wordstat-merged.csv` | все 185 запросов (волны 1+2): запрос, частоты, три «соседних» запроса |
| `wordstat-theme.csv` | волна 1: 102 запроса |
| `wordstat-fetcher.py` | сбор частот по списку запросов (нужен доступ к API — ключ в переменной окружения, в репозитории не хранится) |
| `wordstat-blog-rework.py` | сбор под переработку блога (тот же API, другой набор тем) |

**Как читать частоты.** В таблицах — показы (impressions), не точные запросы: по ним оцениваем
относительный спрос и приоритет темы, а не прогноз трафика.

**Куда ведут данные.** `THEMING.md` → `deliverables/BLOG-REWORK-PLAN.md` (§ 2.4 — решение по каждой
статье) → работа в `site/src/pages/blog/`. Следующая волна тем — там же в § 3.

**Правило.** Собранную семантику не выбрасываем: старые волны остаются в CSV, чтобы видеть, как
меняется спрос и не брать одну тему дважды. Скрипты запускаются из этой папки:

```bash
cd data/wordstat && YANDEX_API_KEY=… python3 wordstat-fetcher.py queries.txt
```
