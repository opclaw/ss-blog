# Smart Solutions — сайт и блог

Боевой сайт живёт в `site/` (Astro, статические страницы с адресами `*.html`). Всё, что делается
для посетителя — страницы, стили, графика, интерактив — только там.

## Где что лежит

| Папка | Что это | Можно ли менять |
|---|---|---|
| `site/` | **боевой сайт и блог** (Astro, страницы, компоненты, стили, проверки) | да, здесь вся работа |
| `data/wordstat/` | семантика: запросы, частоты, тематика (`THEMING.md`, `*.csv`, скрипты сбора) | да, дополняем по мере сбора |
| `deliverables/` | рабочие документы: планы, отчёты, разборы команд, инструкция по выкладке | да, это документы о работе |
| `deliverables/archive/` | история: прогоны команд, отменённые решения, прототипы дизайна, разовый пакет правок прода | по правилу «только чтение» — в архив не возвращаемся |
| `deliverables/screenshots/` | скриншоты приёмки (графика, интерактив) | да |
| `legacy/version-4/` | исходный сайт из архива «version 4» — **эталон для сверки и откат** | нет, только чтение |
| `version 1/`, `version 2/`, `version 3/` | старые версии сайта | нет, не трогать |
| `.github/workflows/` | CI: сборка, проверки, кнопка выкладки на прод | да |

## Проверки одной командой

```bash
cd site && npm ci && npm run check
```

`check` прогоняет семь стадий: сборка → сверка с legacy → актуальность sitemap → JS →
интерактив → **стиль графики** → QA (якоря, ссылки, воронка) → SEO-аудит.
Отдельно: `npm run style` (только графика), `npm run qa`, `npm run audit`.

## Документы, по которым мы работаем

- `deliverables/RELEASE-PLAN.md` — план релиза, что сделано и что ждёт решения владельца;
- `deliverables/BLOG-REWORK-PLAN.md` — переработка статей блога: семантика, приоритеты;
- `deliverables/GRAPHICS-STYLE.md` — правила графики и интерактива (запрет «нейрослопа»);
- `deliverables/WORKSPACE-AUDIT.md` — что в репозитории нужное, что архивное, что удалено;
- `deliverables/DEPLOY-GUIDE.md` — как выкладывать (GitHub Actions → Beget, Vercel);
- `SESSION.md` — журнал шагов (append-only).

## Правила коротко

1. Правки сайта — только в `site/`. `legacy/` и `version N/` — только чтение.
2. Личные панели (Vercel, DNS, Вебмастер, BotFather) — действия владельца; я готовлю точную инструкцию.
3. Формы, `send.php`, cookie-баннер не подключаем; Метрику не отключаем/не меняем без решения владельца.
4. Никаких обещаний и цифр без источника: числа в статьях — либо факт, либо «по нашей оценке».
5. Графику рисуем вектором по `GRAPHICS-STYLE.md`; проверка `npm run style` не даст протащить размытие и растр.
