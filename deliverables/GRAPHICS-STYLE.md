# Графика и интерактив блога: правила против «нейрослопа»

Дата: 2026-09-26. Действует для всех статей блога (`site/src/pages/blog/*.astro`) и компонентов
(`site/src/components/blog/*.astro`). Проверяется автоматически: `cd site && npm run style`
(входит в `npm run check`).

---

## 1. Почему это вообще проблема

«Нейрослоп» в графике узнаётся по пяти признакам, и все они — про отсутствие решений:

1. **Мягкое свечение и размытие** — `filter: blur`, `drop-shadow`, `backdrop-filter`, градиентные
   пятна. Ими закрывают пустоту вместо того, чтобы нарисовать схему.
2. **Размытые края блоков** — тень «в молоко» (`0 20px 40px rgba(...)`), из-за которой карточка
   выглядит приклеенной из другого шаблона.
3. **Растровые картинки-иллюстрации** — «сгенерированная схема», которая мылится при увеличении,
   не совпадает по палитре и весит больше всей статьи.
4. **Стоковый декор без смысла** — полусферы, частицы, светящиеся линии, «сеть из точек» ни к чему.
5. **Цифры ниоткуда** — красивая диаграмма, значения которой не совпадают с текстом статьи.

Наш блог — инженерный документ с расчётами, а не лендинг. Поэтому графику делаем так, как делают
чертежи и отраслевые отчёты: **линия, сетка, число, подпись**. Всё остальное — удаляется.

---

## 2. Что запрещено (проверяет `tools/style-check.py`)

| Запрет | Почему | Чем заменить |
|---|---|---|
| `filter: blur()`, `drop-shadow()`, `backdrop-filter`, `text-shadow` | размытие и свечение = «нужно спрятать пустоту» | плоская заливка, 1px контур |
| тень с размытием больше 2px | «мягкая карточка из шаблона» | «печатная» тень: `box-shadow: 3px 3px 0 0 var(--paper2)` или контур |
| `radial-gradient` (пятна, свечения) | ровно тот приём, по которому узнают генеративный дизайн | `repeating-linear-gradient` 1px — «миллиметровка», либо ничего |
| `<img>`, `<picture>`, `background-image: url(...)` в статьях | растр мылится при зуме, ломает палитру, весит мегабайты | инлайновый SVG в компоненте |
| `<linearGradient>`, `<radialGradient>`, `<filter>`, `<feGaussianBlur>`, `<mask>` внутри SVG | градиент и фильтр в схеме — декор, а не информация | сплошной `fill` токеном палитры |
| фигура без класса `fig` | без него не работает зум и подпись читается как текст | `<figure class="fig bl-fig">` |

Исключения (осознанные, не в блоге): шапка и подвал сайта из `styles.css` живут по своим правилам,
их не трогаем; в блоге стили сайта не переопределяем, а изолируем (см. § 4).

## 3. Что делаем вместо

1. **Вектор.** Любая схема — инлайновый SVG с `viewBox`, значит масштабируется без потерь и печатается.
2. **Палитра — токены светлого листа.** `--ink #101014`, `--paper #FAFAF7`, `--acc-t #0A7EA4`,
   `--green #0E9F6E`, `--line #E4E4DE`. Цвет в схеме несёт смысл: зелёный — «стало лучше»,
   оранжевый/красный — «потери», серый — «как было», голубой — «действие ИИ».
3. **Печатная тень и чёткие края.** Карточка фигуры: 1px контур + смещение 3px без размытия.
   Никаких размытых границ — блок читается как вставка в документ.
4. **Шкала и сетка.** У диаграмм — «красивые» деления (шаг 1/2/5×10ⁿ, целые подписи), у схем —
   выравнивание по пиксельной сетке, у таблиц — 1px линии.
5. **Числа из текста.** Компонент не придумывает значения: они приходят из статьи, а в подписи
   сказано, откуда взяты («середина вилки 6–8 часов из расчёта выше»). Числа — моноширинным.
6. **Движение только по делу.** Анимация допустима, если показывает процесс (проезд сканера,
   переключение этапа). Она выключается при `prefers-reduced-motion`, и без JS всё видно.

## 4. Почему на светлом листе не «протекает» старая тёмная тема

`styles.css` сайта написан для тёмного фона. Внутри статьи мы **не переписываем его глобально**
(им пользуются другие страницы), а подменяем переменные в области `.bl-sheet`:

```css
.bl-sheet{ --bg:#FAFAF7; --bg-elevated:#FFFFFF; --card-bg:#FFFFFF; --border:#E4E4DE; --accent:#0A7EA4; }
```

Тогда legacy-блоки (`fig`, `weeks-grid`, `err-card`, `pull-quote`, `formula-card`) берут светлую
палитру, а не инверсную. Плюс явные правила для схем: `.bl-sheet .f-warn{fill:#B45309}` и т.п.

## 5. Компоненты: что чем рисовать

| Компонент | Когда | Пример |
|---|---|---|
| `FigBars.astro` | сравнить 2–4 величины (было/стало, по ролям, по каналам) | бухгалтерия: 7,0 ч → 1,8 ч на сверку; производство: 15 700 / 25 130 / 7 850 ₽ |
| `FigRows.astro` | длинные подписи, доли, диапазоны; есть режим `before` — пунктиром «как было» | медцентр: неявки 17,5 % → 5,5 % |
| `HeroArt.astro` | схема в шапке статьи: 6 вариантов (`flow`, `doc`, `calc`, `nodes`, `chat`, `steps`) | «заявка → ИИ → человек» |
| `Calc`, `Checklist`, `Timeline`, `Tabs`, `Matrix`, `Sources`, `Funnel`, `DocScan`, `Prompt` | интерактив: расчёт, готовность, этапы, сравнение, доказательства | калькулятор ROI, чек-лист с вердиктом |

Придумали новый тип диаграммы — добавляйте компонент, а не картинку, и держите те же правила.

## 6. Как проверить глазами (без браузера в песочнице)

1. Запустить превью: `cd site && npm run preview` → открыть `/blog/<статья>.html`.
2. Увеличить схему: фигуры кликабельны (`cursor: zoom-in`, класс `fig`), — вектор не мылится.
   Именно это отличает нашу графику от сгенерированной картинки.
3. Отключить JS и посмотреть статью снова: все числа диаграмм остаются на месте (они в разметке),
   интерактив показывает базовое состояние.

## 7. Чек-лист приёмки новой графики (для команды)

- [ ] `npm run style` — без нарушений.
- [ ] у каждой фигуры есть номер и подпись: «что это и откуда числа»;
- [ ] значения в фигуре совпадают с числами в тексте статьи (проверка вручную, глазами);
- [ ] диапазоны подписаны как диапазоны («6–8 ч»), а не как точная цифра;
- [ ] на 390px нет горизонтального скролла, подписи не обрезаны;
- [ ] контраст текста в схеме ≥ 4.5:1 (светлые «чернила» старой темы перекрашены);
- [ ] фигура не дублирует то, что сказано абзацем рядом.
