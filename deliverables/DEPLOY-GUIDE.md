# Как выложить обновление (2026-09-25)

Три пути. Первые два — про текущий домен `smartsolutions.today` (хостинг Beget, Apache),
третий — про Vercel. Выбирайте по обстоятельствам; я могу делать всё, кроме действий
в ваших личных панелях (Vercel, DNS, Вебмастер).

---

## Путь 1. Кнопка в GitHub — рекомендую (нужны доступы один раз)

Ничего запускать локально не надо: сборка, проверки, выгрузка, проверка прода и уведомление
Яндекса/Bing идут на серверах GitHub.

**Подготовка (один раз, 3 минуты):**

1. Откройте https://github.com/opclaw/ss-blog/settings/secrets/actions
2. «New repository secret» — добавьте три обязательных:
   - `BEGET_USER` — логин хостинга (например `smartsol`)
   - `BEGET_HOST` — хост (например `smartsol.beget.tech` или IP)
   - `BEGET_PATH` — путь до папки сайта (например `/home/smartsol/smartsolutions.today/public_html`)
3. Если на хостинге вход по SSH-ключу, добавьте ещё два:
   - `BEGET_SSH_KEY` — приватный ключ целиком (от `-----BEGIN` до `-----END`)
   - `BEGET_PORT` — порт SSH, если не 22

**Выкладка (одна кнопка):**

1. https://github.com/opclaw/ss-blog/actions/workflows/site.yml
2. Справа «Run workflow» → ветка `arena/01a0d848-ss-blog` (для текущего обновления)
   или `main` (когда решите, что всё готово и пора зафиксировать) →
   галочка **«Выложить сборку на прод»** → Run workflow.
3. Смотрите лог: 6 шагов `release.sh`. В конце он сам проверит прод по 29 адресам
   и отправит IndexNow. Через 1–2 минуты обновление на сайте.

**Как это устроено:** джоба `deploy` запускается **только** при ручном нажатии с галочкой.
Обычные коммиты и пул-реквесты деплой не трогают — решение о релизе остаётся за вами.

## Путь 2. Локально одной командой (если GitHub-секреты заводить не хочется)

```bash
cd /home/user/ss-blog/site
BEGET_USER=логин BEGET_HOST=хост BEGET_PATH=~/smartsolutions.today/public_html ./release.sh
```

Полезные режимы:

```bash
./release.sh --dry-run        # ничего не выгружать: показать, что поедет
./release.sh --skip-rsync     # прод уже обновлён: только проверка прода + IndexNow
```

Скрипт делает: сборка → все проверки (`npm run check`) → rsync `dist/` на хостинг
(с `--delete`, исключая `.well-known` и `.md`) → проверка 29 адресов на проде →
IndexNow (Яндекс и Bing; Google — только sitemap и Search Console).

## Путь 3. Vercel

**Что уже есть (ничего делать не надо):** Vercel подключён к репозиторию. На каждый мой коммит
он собирает **Preview**, на пуши в `main` — **Production**. Последний production-деплой
(`main`, коммит `88bec6a`) собран сегодня.

**Важно про доступ:** у проекта включена защита деплоев (Vercel Authentication) — превью
и прод открываются только после входа в аккаунт Vercel. Поэтому ссылка вида
`https://ss-blog-6b11o8y0v-opclaws-projects-1b852b6a.vercel.app` у вас откроется, а у коллеги
без аккаунта — попросит логин. Если нужно, чтобы смотрели все:
Vercel → проект `ss-blog` → Settings → Deployment Protection → Vercel Authentication → **Disabled**.

**Чтобы обновление стало продом на Vercel:** нужно, чтобы коммиты попали в `main`.
Сейчас вся работа лежит в ветке `arena/01a0d848-ss-blog` и ждёт решения по PR #3.
Как только PR влит в `main`, Vercel сам соберёт Production за 1–2 минуты.
Влить могу я — скажите слово, это одно действие.

**Чтобы Vercel стал основным хостингом для домена `smartsolutions.today`**
(это уже перенос, а не выкладка):

1. Vercel → проект → Settings → Domains → Add → `smartsolutions.today` и `www.smartsolutions.today`.
2. У регистратора домена (или в панели Beget, где сейчас DNS) поменять DNS:
   - A-запись для `@` → `76.76.21.21`
   - CNAME для `www` → `cname.vercel-dns.com`
   сейчас `smartsolutions.today` указывает на `87.236.16.206` (Beget).
3. Дождаться выпуска сертификата (Vercel сам), проверить, что 29 адресов открываются,
   и только после этого отключать старый хостинг — почта и прочие сервисы Beget, если они есть,
   при смене A-записи не пострадают, но проверить стоит.
4. Не забыть перенести `public/.htaccess`-правила в `vercel.json` (редиректы и заголовки):
   скажите — подготовлю конфиг и проверю редиректы на превью.

**Небольшая честная ремарка:** для сайта без серверной логики Vercel подходит, но у текущего
хостинга есть российский IP (это плюс для Яндекса по скорости в РФ) и Apache-правила,
которые уже работают. Перенос на Vercel стоит делать, если вам важнее удобство деплоя из GitHub,
чем близость к российской аудитории. Разница по скорости для Яндекса замеряемая — если переносить,
лучше сначала прогнать сравнение на превью.

## После любой выкладки — 5 минут руками (нужны панели)

1. Яндекс.Вебмастер → Индексирование → Файлы Sitemap: переотправить `sitemap.xml`.
2. Там же → Переобход страниц: добавить 5 главных адресов (новая статья, посадочные, `/blog/`).
3. Вебмастер → Диагностика: убедиться, что ошибок нет.
4. Метрика → Цели: проверить, что цели ловят клики (Telegram, телефон, WhatsApp, e-mail).
5. Записать дату релиза в `SESSION.md` — это baseline для недельной динамики.
