# Команды 2026-10: три последовательных рефакторинга сайта

Три захода по всему сайту (32 страницы: главная, услуги, хаб `/ai.html`, три посадочные,
21 статья блога, 3 кейса, 404), каждый следующий принимает **замороженный** результат предыдущего.

| № | Файл команды | Что делает | Отчёт | Коммиты |
|---|---|---|---|---|
| 1 | `01-teksty-smysly-cifry.md` | Тексты, смыслы, логика, сопоставление цифр и расчётов | `deliverables/TEAM-RUN-18.md` | `content:`, `fix:`, `docs:` |
| 2 | `02-kod-verstka-perelinkovka.md` | Код, вёрстка, перелинковка, вес страниц | `deliverables/TEAM-RUN-19.md` | `refactor:`, `style:`, `perf:` |
| 3 | `03-seo.md` | Полный SEO-рефакторинг | `deliverables/TEAM-RUN-20.md` | `seo:`, `docs:` |

## Почему порядок именно такой

1. **Смыслы → код.** Вёрстку нельзя править по меняющемуся тексту: цифры и формулировки
   меняют длины строк, таблицы, заголовки и мобильную раскладку. Сначала фиксируем смысл и цифры,
   потом под них подгоняем код и вёрстку.
2. **Код → SEO.** Мета-теги, схемы `JSON-LD` и перелинковка завязаны на финальные заголовки,
   ссылки и структуру. Если SEO-команда пройдёт раньше, её работа частично обесценится правками.

## Как запускать

1. Открыть новую сессию в ветке `arena/498e9471-ss-blog` (эта сессия и эта ветка — та же работа;
   ветку не менять).
2. Вставить в чат **целиком** текст одного файла команды — это и есть задание сессии.
3. Команда работает, коммитит и пушит в `arena/498e9471-ss-blog`, пишет отчёт `TEAM-RUN-N.md`,
   дописывает `SESSION.md`.
4. Следующая команда стартует **только** когда: `npm run check` в `site/` зелёный на последнем
   коммите, отчёт предыдущей команды лежит в репозитории, дерево чистое.

Запускать можно и в этой же сессии — по одному заходу, с паузой между командами
(владелец смотрит результат предыдущей).

Правило эстафеты: команда **не переделывает работу предыдущей**. Нашла дефект в её зоне —
пишет в отчёте раздел «Возврат предыдущей команде», правит только механические мелочи
(опечатка, битая ссылка) и фиксирует это в отчёте.

## Общие правила для всех трёх команд

- Прочитать `CLAUDE.md` (особенно §4 «Workflow» и §5 «Запрещённые действия»), `SESSION.md`,
  `MODEL-ROUTING.md`, `CONTENT-MAP.md`.
- Работаем в `site/`. Сборка и проверка: `cd site && npm run check` — зелёный до коммита.
- Состав команды — от 10 ролей, обязательны критики (читатель, скептик, эксперт предметной
  области) и отдельный проверяющий, который ничего не писал своей рукой.
- Отчёт — результат, а не пересказ процесса: что нашли, что сделали, чем доказали, что осталось
  за владельцем (образец — `deliverables/TEAM-RUN-17.md`).
- **Стоп-условия (выход к владельцу, а не самовольное решение):** цены, позиционирование,
  продукты, адреса страниц `*.html`, навигация главной, включение/выключение Метрики,
  `send.php` и формы, правки `legacy/`. См. `CLAUDE.md` §5.
- Коммиты — conventional commits, по одной логической правке на коммит, push только
  в `arena/498e9471-ss-blog`.
- Если среда сбросилась (пропали `node_modules`, `dist`, `/tmp`): `git fetch -q origin <ветка> &&
  git reset --mixed FETCH_HEAD`, затем `npm ci && npm run build`, затем браузерные аудиты
  (`playwright-core` + `@sparticuz/chromium` в `/tmp/pw2`, распаковка `al2023` в `/tmp/al2023`).
  Подробности — в `SESSION.md`, «Известные грабли».
- Не имитировать проверку: если инструмент недоступен (нет сети, нет браузера), команда пишет
  об этом в отчёте прямо, а не подменяет проверку словами.

## Что смотреть в конце каждой команды (приёмка владельцем)

1. Отчёт `TEAM-RUN-N.md`: находки → правки → замеры → за владельцем.
2. Зелёный `npm run check`.
3. Живое превью (сборка) — 2–3 страницы, которые команда назвала рискованными.
4. `git log` — понятные сообщения, нет коммитов «ещё правки».
