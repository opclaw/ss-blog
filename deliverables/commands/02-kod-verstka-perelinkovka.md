## 1. Цель захода

Принять замороженные тексты и цифры и привести под них **код и вёрстку** в порядок, а также
навести порядок в **перелинковке**. Вопрос захода:

> «Код можно поддерживать, вёрстка не разъезжается, а по ссылкам можно дойти куда угодно
> за три клика?»

Четыре вещи:

1. **Код.** Убрать мёртвый CSS/JS, дубли компонентов, случайные инлайновые стили; привести
   страницы к общим компонентам и токенам; уменьшить вес (`index.html` ~558 КБ, `styles.css`
   ~113 КБ, `script.js` ~21 КБ — сегодня это самые тяжёлые места сайта).
2. **Вёрстка.** Все страницы на всех ширинах без переполнений, обрезок и горизонтального скролла;
   типографика (Manrope/Inter/JetBrains Mono), неразрывные пробелы в числах, цели касания ≥44 px.
3. **Перелинковка.** Карта ссылок сайта: нет страниц-сирот, глубина от главной ≤3 кликов,
   осмысленные анкоры, статьи ведут в деньги, посадочные — в статьи и соседние посадочные.
4. **Интерактив.** Кит-блоки и калькуляторы работают на всех страницах, где стоят; без JS
   страница остаётся рабочей.

## 2. Границы

**Делает:** классы, компоненты `.astro`, CSS/JS, разметку, атрибуты, ссылки и анкоры,
вес страниц, доступность разметки.

**Не делает:** не переписывает тексты и цифры (это команда 1; нашла смысловой дефект — пишет
в отчёт раздел «Возврат команде 1»), не меняет адреса страниц, не трогает SEO-мету, схемы
`JSON-LD`, `robots.txt`, `sitemap.xml` (это команда 3), не трогает `legacy/`.

Исключение по мелочам: опечатка или битая ссылка по пути — правится сразу с пометкой в отчёте.

## 3. Состав команды (роли и вопросы)

| Роль | Вопрос |

| **Инженер-фронтенд** | Как устроен код и что в нём лишнее? Где дубли и мёртвые правила? |

| **Дизайн-контролёр** | Элементы соответствуют дизайн-системе (токены, радиусы, тени «печатные»)? |
| **Специалист по доступности** | Фокус, клавиатура, подписи, `aria`, контраст, цели касания 44+ px? |
| **Отвечающий за перелинковку** | Граф ссылок: сироты, тупики, глубина, анкоры, «Смотрите также»? |
| **Интерактив-инженер** | Работают ли киты и калькуляторы на всех страницах и без JS? |
| **Производительность** | Вес страниц и ресурсов: что можно убрать без потери смысла? |

| **Проверяющий** | Прогон всех аудитов до/после; сам не правит ни строки. |

## 4. Порядок работы

**Проход 0 — карта ссылок (главный артефакт захода).** Написать инструмент
`site/tools/audit-links.mjs`: строит граф внутренних ссылок из `site/dist` и печатает —
страницы-сироты (0 входящих), глубину от `/` до каждой страницы, страницы без ссылки в деньги,
ссылки с анкорами вида «здесь/подробнее/читать», ссылки на несуществующие адреса и на `/404.html`.
Положить сводку в отчёт. Без этой карты перелинковку не «улучшать».

**Проход 1 — аудит кода и вёрстки.**
- Baseline: `npm run check`, `npm run qa`.
- Браузерные аудиты (нужен Playwright: `playwright-core` + `@sparticuz/chromium` в `/tmp/pw2`,
  библиотеки — в `/tmp/al2023`, запуск с `LD_LIBRARY_PATH=/tmp/al2023/lib`):
  `node tools/audit-visual.mjs`, `node tools/audit-numbering.mjs`, `node tools/audit-figtext.mjs`,
  `node tools/audit-figures.mjs --base http://127.0.0.1:4321`.
- Текстовый регресс от команды 1: `python3 tools/audit-text.py`.
- `node tools/audit-layout.mjs --only <page>` по изменённым страницам (~20 с на страницу);
  полный прогон — перед передачей команде 3.
- Ручной обзор: поиск `style="` в разметке, поиск классов, которых нет в CSS, и правил, которых
  нет в разметке (мёртвый CSS); дубли компонентов лендингов и блога.

**Проход 2 — правки.** Сначала то, что чинит риск (переполнения, битые ссылки, сироты), затем
гигиена кода и вес. Каждая правка — с проверкой до/после в отчёте.

**Проход 3 — перелинковка.** По карте: убрать сирот, выровнять глубину, переписать слабые анкоры
на осмысленные, добавить недостающие связи (статья → парная посадочная → `/services.html`;
посадочная → статья + соседняя посадочная), проверить блоки «Смотрите также» и меню/подвал.
Правило: ссылка ради ссылки не добавляется — только там, где она помогает читателю.

## 5. Приёмка захода

| Критерий | Порог |
|---|---|
| Переполнения и скролл | 0 на всех 32 страницах × ширины 320/360/390/414/768/1024/1280/1440/1920 |
| `audit-layout` | 0 замечаний на полном прогоне |
| Граф ссылок | 0 сирот; глубина от главной ≤3; у каждой статьи ≥3 исходящих осмысленных ссылок; у каждой посадочной ≥2 входящих |
| Анкоры | 0 ссылок «здесь», «подробнее», «читать» без предмета |
| Интерактив | все киты/калькуляторы: работает, пересчитывает, без JS страница читается |
| Ошибки JS | 0 на всех страницах (`js-check`) |
| Вес | HTML главной ≤450 КБ после оптимизаций (или объяснено, почему нельзя), `styles.css` без мёртвых правил |
| Инструменты | `npm run check` зелёный; полный `audit-layout` зелёный |
| Доступность | `qa-check` без замечаний, цели касания ≥44 px |
