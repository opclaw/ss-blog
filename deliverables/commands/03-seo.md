## 1. Цель захода

Полный SEO-рефакторинг сайта на **замороженных** текстах (команда 1) и **финальной** разметке
(команда 2). Вопрос захода:

> «Каждая страница честно и точно отвечает на свой запрос, и поисковик понимает это без
> догадок?»

Пять направлений:

1. **Мета и заголовки.** `title`, `description`, `H1`, `H2` — длины, уникальность, соответствие
   интенту и видимому тексту страницы.
2. **Семантика.** Сопоставление страниц с запросами по `CONTENT-MAP.md` и данным Wordstat;
   защита от каннибализации (посадочная ↔ парная статья, две статьи об одном).
3. **Микроразметка.** `JSON-LD`: типы, обязательные поля, соответствие видимому содержимому.
4. **Техническая индексация.** `canonical`, `robots.txt`, `sitemap.xml`, `.htaccess`, страница 404,
   служебные файлы, дубли адресов.
5. **Внутренние ссылки глазами SEO.** Анкоры, глубина, распределение веса, отсутствие тупиков.

## 2. Границы

**Делает:** мета-теги, заголовки (H1/H2 — только как SEO-дефект: дубль, отсутствие, несоответствие
адресу), микроразметку, `robots.txt`, `sitemap.xml`, `.htaccess`, `og:*`, служебные файлы,
рекомендации по ссылкам. Готовит список действий для владельца (Вебмастер, Search Console, IndexNow).

**Не делает:** не меняет тексты страниц (кроме исправления явных SEO-дефектов заголовков — с
пометкой в отчёте), не меняет вёрстку и код, **не меняет адреса страниц `*.html`** (запрет
`CLAUDE.md` §5: на них завязаны внешние ссылки, `.htaccess`, sitemap), не включает/выключает
Метрику, не трогает `legacy/`.

## 4. Порядок работы

**Проход 0 — baseline и карта «страница ↔ запрос» (без правок).**
- `cd site && npm run audit` (это `tools/seo-audit.py`: мета, схемы, вес, robots, sitemap, .htaccess).
- Пересобрать таблицу «адрес → интент → целевой запрос → текущие title/H1» на 32 страницы,
  сверяя с `CONTENT-MAP.md` §1.1 и `data/wordstat/wordstat-merged.csv` (Россия, 30 дней, 185 запросов).
- Явно отметить пары, где зоны пересекаются: `ai-agenty.html` ↔ `blog/chto-takoe-ii-agent.html`,
  `avtomatizaciya-prodazh.html` ↔ `blog/ii-dlya-prodazh.html`, `ii-assistent-dlya-sajta.html`
  (парной статьи нет — место в карте зарезервировано).

**Проход 1 — мета и заголовки.** Правила: `title` 40–65, `description` 120–175, без дублей,
ключ страницы не выносится в title/H1/H2 чужой страницы; H1 — ровно один, совпадает по смыслу
с title; заголовки описывают содержимое, а не «SEO по-старому» (никаких перечислений городов,
«лучший», «недорого»). Пустой или шаблонный description — дефект.

**Проход 2 — микроразметка.** Проверить и, где нужно, добавить:
- главная: `Organization` + `WebSite`;
- статьи: `Article`/`BlogPosting` (+ автор из `src/data/site.ts`, даты), `FAQPage` (только если
  FAQ виден), `BreadcrumbList`;
- разделы и посадочные: `BreadcrumbList`; при необходимости `Service` — но только если текст
  страницы его подтверждает (никаких выдуманных `ratingValue`, `offers` с ценами, которых нет);
- кейсы: `Article`/`CreativeWork` по факту содержимого.
Схемы валидировать синтаксически и на совпадение с видимым текстом (для `FAQPage` — ответы
должны быть на странице дословно).

**Проход 3 — техническая индексация.**
- `canonical` на каждой странице = её собственный адрес; у 404 canonical нет (уже так — не сломать).
- `robots.txt`: не закрывать нужное (сборка, `search-index.json`, шрифты), не оставлять
  устаревших директив; `sitemap.xml` — 31 адрес, без `/404.html`, с `lastmod`.
- `.htaccess`: проверка закрытий/редиректов, отдача 404, доступность `/search-index.json`.
- Дубли адресов: `/` и `/index.html`, регистр, слэш; смешанный контент; `rel=noopener` у внешних.
- Проверки: `npm run check` (внутри `make-sitemap --check`, `check-404.mjs`, `js-check`, `kit-check`,
  `style-check`, `qa-check`), затем `python3 tools/verify-prod.py` на живом проде — после выкладки,
  не раньше (из песочницы внешняя сеть недоступна — писать так прямо, если не выйдет).

**Проход 4 — внутренние ссылки глазами SEO.** Совместно с картой из команды 2
(`tools/audit-links.mjs`): глубина, анкоры, «Смотрите также», нет ссылок на `/404.html`,
нет ссылок с `nofollow` по внутренним адресам.

**Проход 5 — действия после выкладки (список владельцу).** Яндекс.Вебмастер: переобход 31 адреса,
отправка sitemap, проверка robots, «Неканонические страницы»; Google Search Console: sitemap,
проверка покрытия; `node tools/indexnow.mjs` (сначала сухой прогон, отправка — только после
реальной выкладки на прод, по согласованию). Никаких обещаний «попадём в топ» — только проверяемые
шаги.
