# Переработка блога: аудит 20 статей и план (2026-09-25)

Цель (из задачи): блог приводит клиентов на внедрение ИИ, обгоняет detistov.ru и не читается как «нейрослоп».
Эталон формы — статья «Что такое ИИ-агент» (v6): светлый лист, графика, интерактив, шапка сайта.

## 1. Команды и роли

| Отдел | Роли | За что отвечает | Может остановить публикацию? |
|---|---|---|---|
| **Главный редактор (архитектор)** | 1 | Решения по статье, разрешает споры отделов, держит цель «заявка на аудит» | да |

| **Маркетинг** | продуктовый маркетолог, стратег по воронке | Одна мысль статьи, связь с услугами (services.html, ai.html), где и как читатель переходит к аудиту | нет |
| **Контент** | отраслевой автор, редактор «антишаблон», фактчекер | Текст на живом языке отрасли, у каждой статьи своя структура, каждая цифра с источником или помечена как пример | да (фактчекер) |
| **Дизайн** | главный дизайнер, инфографик, моушн-дизайнер, дизайнер интерактива | Один главный интерактив на статью и 2–4 поддерживающих, графики, анимации со смыслом | нет |

| **Критики 1: читатели** | владелец бизнеса из отрасли, скептик «опять ИИ продают», новичок | «Понял ли я, что мне делать, и поверил ли?» | нет, но замечания обязательны |
| **Критики 2: качество** | асессор Яндекса (польза, экспертность), детектор шаблонности, эстет | «Похоже ли это на 100 других статей? Есть ли опыт автора?» | да |
| **Проверяторы (автоматика)** | `npm run check` + новые проверки | Шапка/меню/подвал, ссылки, JS, утечки стилей, запретные формулировки | да |

Порядок работы над статьёй (каждый шаг — «ворота», дальше только после «да»):
1. SEO: главный запрос, частота, интент по выдаче, 5–10 дополнительных запросов.
2. Маркетинг + редактор: одна мысль, план из разделов **именно для этой отрасли** (не общий костяк).
3. Дизайн: какой интерактив и какие графики, эскиз в словах.
4. Автор пишет → фактчекер помечает каждую цифру: `источник` / `пример расчёта` / `нужно от Олега`.
5. Разработка собирает из компонентов.
6. Критики 1 и 2 → правки → проверки → публикация.

## 2. Что нашли в написанных статьях

### 2.1 Брак, исправлен сразу
- **Заголовки из техзадания на сайте** в 5 статьях (бухгалтерия, недвижимость, онлайн-школа, ресторан, турагентство):
  «Расчёт эффекта с числами: управляющий/маркетолог ресторана, часы … вручную vs с ИИ; рубли».
  Они стояли в H2 и в оглавлении. Заменены на человеческие.
- Опечатка «обработить» (ИИ в CRM).
- В статье v6: логотип в шапке был чёрным, оглавление — серым (стили статьи перебивали стили сайта). Исправлено, и добавлена защита от повторения.

### 2.2 Системная проблема: одна статья, 18 раз
| Признак | Сколько статей |
|---|---|
| 12–13 разделов H2 | 20 из 20 |
| Ровно 6 вопросов в FAQ | 18 |
| Ровно 8 SVG-графиков | 16 |
| Ни одной таблицы | 19 |
| Разделы «Пилот 2–4 недели», «Частые ошибки», «Чек-лист готовности» | 13 |
| Первый раздел «Где [отрасль] теряет [клиентов]…» | почти все отраслевые |

Для Яндекса и для читателя это одна статья с подставленной отраслью (исключение — «Как посчитать эффект»: своя структура и таблица). Это главный риск «нейрослопа», и лечится он переписыванием, а не правками.

### 2.3 Цифры без источника и кейсы под вопросом
- **Недвижимость:** «Мы внедряли такую схему в агентстве с 12 агентами… время ответа с 35 минут до 47 секунд, доля ответов в 5 минут с 40 % до 92 %». На сайте такого кейса нет. **Если проекта не было — удалить. Если был — нужны подробности от Олега.**
- **H1 с обещаниями:** «первичка и сверки в 6 раз быстрее» (бухгалтерия), «заявки в 4 раза быстрее» (продажи). Цифры получены из собственного примера (6 мин против 1 мин), а в заголовке выглядят как факт.
- **«По оценке аналитиков… 15–20 % запросов в рунете» (GEO)** — нет ссылки на источник.
- **Медцентр:** «no-show 15–20 % → 4–7 %», «от 15 до 30 % записей» — без источника.
- «До 40 % рабочего времени» встречается в 4 статьях в разных вариантах — признак шаблона.

Правило для переписывания: каждая цифра — либо ссылка на источник, либо явно «пример: подставьте свои» (как калькулятор в v6), либо пометка `[нужно от Олега]`.

## 3. Библиотека интерактива (общие компоненты Astro)

Сейчас весь интерактив v6 — один скрипт на одну статью. Для 60+ статей нужны общие компоненты: написали один раз, настраиваем данными.

| Компонент | Что делает | Где уже есть / куда пойдёт |
|---|---|---|
| `<Calc>` | Ползунки → часы, рубли, сотрудники; формула с сайта (часы × ставка − стоимость) | v6; все отраслевые статьи, «Как посчитать» |
| `<Tabs>` / `<Compare>` | Переключение «было / стало», «чат-бот / агент», проигрывание диалога | v6; CRM, продажи, ресторан |
| `<Loop>` | Цикл шагов с бегущей точкой и описанием шага | v6; агенты, логистика, производство |
| `<Checklist>` | Отметки → шкала и вердикт «можно начинать пилот» | v6; все статьи вместо одинакового чек-листа |
| `<Funnel>` | Воронка с «утечками», ползунки потерь | продажи, медцентр, онлайн-школа |
| `<Race>` | Анимация «скорость ответа: 35 мин против 2 мин» | недвижимость, продажи |
| `<DocScan>` | Документ → подсвеченные поля и риски | бухгалтерия, юристы, строительство |
| `<Timeline>` | Путь заказа или заявки с узкими местами | логистика, производство |
| `<Budget>` | Галочки → вилка бюджета по ценам сайта | стоимость внедрения |
| `<Sources>` | «Как Нейро собирает ответ»: источники → ответ | GEO |
| `<Bars>`, `<Table>` | Анимированные столбики, таблица с выделенной колонкой | везде |
| `<Prompt>` | Промпт с кнопкой «скопировать» | v6; все статьи |

Правила дизайн-команды для интерактива:
- в каждой статье **один главный** интерактив, придуманный под задачу этой отрасли, и 2–4 поддерживающих;
- движение объясняет процесс, а не украшает;
- без JavaScript видна статичная версия с тем же смыслом (важно для поисковиков);
- `prefers-reduced-motion` отключает анимации;
- цвета только из системы сайта (#00D9FF для графики, #0A7EA4 для текста на светлом), без курсива и эмодзи (CLAUDE.md).

Проверки, которые добавятся в `npm run check`:
- каждый интерактив работает (как проверка калькулятора в этот раз);
- утечек стилей нет (уже есть);
- запретные фразы: «vs», «/», «[…]» в заголовках, «в N раз» в H1, «по оценке аналитиков» без ссылки;
- шаблонность: одинаковые H2 в разных статьях, одинаковое число вопросов в FAQ.

## 5. Что нужно от Олега

1. **Кейс в статье про недвижимость:** был проект (агентство, 12 агентов, 35 мин → 47 с) или нет?
2. Реальные кейсы по ИИ, хотя бы 2–3 без названий компаний: задача, что сделали, цифры.
3. Фото для подписи автора.
4. Мнение «против течения» (где ИИ не нужен).
5. Данные Вебмастера: по каким запросам статьи уже показываются. От этого зависит, что переписывать полностью, а что осторожно.
6. Частоты Wordstat (`deliverables/ONE-CLICK-WORDSTAT.md`, из песочницы API недоступен):
   ии для недвижимости, ии для медицинского центра, ии в медицине, ии для онлайн школы, ии для салона красоты,
   ии для турагентства, ии в строительстве, автоматизация строительства, ии в логистике, автоматизация логистики,
   ии на производстве, ии в crm, ии в битрикс24, ии в amocrm, стоимость внедрения ии, окупаемость ии,
   сервисы ии для юристов, нейросеть для юристов.
