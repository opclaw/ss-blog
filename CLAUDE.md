## 3. Технический стек

- **Фронт:** Astro 7 (static, `build.format: preserve` — адреса `*.html` не меняются) + CSS + Vanilla JS.
  Node 22, сборка — `npm run build`, результат в `site/dist/`.
- **Аналитика:** Яндекс.Метрика 106747750 стоит на всех 28 страницах (cookie-баннера нет).
  Включена/выключена — `metrikaId` в `site/src/data/site.ts`. Отключение — только по согласованию.
- **SEO:** `robots.txt` (с явным разрешением ИИ-краулеров и `Clean-param` для Яндекса),
  `sitemap.xml` (генерируется из сборки: `npm run sitemap`), Schema.org (Article + FAQPage + BreadcrumbList
  в статьях; на главной/услугах/кейсах схемы пока нет), `.htaccess`, canonical на всех страницах.
- **Проверки:** `npm run check` = сборка → сверка с `legacy/version-4` → sitemap актуален →
  JS на всех страницах → интерактив kit → SEO-аудит (`npm run audit`). То же гоняется в GitHub Actions.
- **Деплой:** Vercel (preview `ss-ai-preview.vercel.app`) → Beget (prod, rsync `site/dist/`).
- **Графика:** SVG-фигуры рисуются вручную в статьях (2–3 шт/статья, данные из текста).
- **CSS-токены:** переменные в `:root` (цвета, шрифты, отступы), бан-лист идей в голове (нет cyan/purple, нет эмодзи, нет курсива).

### Блог: правила
- Статья = H1, лид, 10–12 H2, FAQ×5, TL;DR, 2–3 SVG-фигуры, CTA.
- Автор: «Олег Кречетов, основатель Smart Solutions» + Schema Person.
- Schema: Article + FAQPage + BreadcrumbList (в статьях нового образца строится из данных `Article.astro`).
- Статьи нового образца — макет `src/layouts/Article.astro` + библиотека `src/components/blog/` и
  `public/blog-assets/kit.{css,js}`; эталон — `blog/ii-dlya-yuristov.astro`. Остальные 20 статей пока на
  старом макете `Base.astro` — при переписывании переводить на `Article.astro`.
- Запреты в тексте: «революция», «магия», «просто посадить», неподтверждённые цифры без пометки «оценка/пример».

## 4. Workflow сессий

### В начале каждой сессии
1. Прочитать этот `CLAUDE.md`.
2. Прочитать `SESSION.md`.
3. `MODEL-ROUTING.md` (какая модель на какую задачу) в репозитории нет — он потерялся при переносе.
   Пока ориентир: черновики статей — k2.7/Ollama, дизайн-черновики — DeepSeek Pro (итог слепого теста),
   редактура, схемы и приёмка — старшая модель. Восстановить файл — задача из плана.
4. Проверить `git status` и текущую ветку.
5. Убедиться, что работаем в `site/`.

### Как ведём задачи (договорённость 2026-09-25)
1. Каждая задача выполняется командой ролей, а не «в одну голову»: состав — от 10 ролей,
   обязательны критики (читатель, скептик, эксперт предметной области) и отдельный проверяющий.
2. У каждой задачи фиксируем: варианты решения и почему выбран один, что сделано, чем проверено.
   Отчёт — `deliverables/TEAM-RUN-*.md`; результат команды, а не пересказ процесса.
3. Ничего не публикуем, пока `npm run check` в `site/` не зелёный; проверки — часть работы команды.

### Во время работы
1. После каждого значимого шага обновлять `SESSION.md` (append, не overwrite).
2. Перед коммитом проверять, что изменения затрагивают только нужные файлы.
3. **Не коммитить `.claude/`, `.DS_Store`, `.vercel/`, `node_modules/`, `dist/`** — `site/.gitignore` настроен.
   `dist/` собирается заново, артефакты сборки в git не нужны.
4. Коммиты — conventional commits: `feat:`, `fix:`, `content:`, `style:`, `seo:`, `deploy:`, `docs:`, `chore:`.

### В конце сессии
1. Обновить `SESSION.md`: что сделано, что не доделано, следующие шаги.
2. Если были открытия — сохранить их в `SESSION.md` (у `MODEL-ROUTING.md` см. п. 4.1) или в skills.
3. Прогнать `npm run check` в `site/` — сборка и все проверки должны быть зелёными.
