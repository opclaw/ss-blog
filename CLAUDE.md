## 3. Технический стек

- **Фронт:** Astro 7 (static, `build.format: preserve` — адреса `*.html` не меняются) + CSS + Vanilla JS.
  Node 22, сборка — `npm run build`, результат в `site/dist/`.
- **Аналитика:** Яндекс.Метрика 106747750 стоит на всех 31 странице (cookie-баннера нет).
  Включена/выключена — `metrikaId` в `site/src/data/site.ts`. Отключение — только по согласованию.
- **SEO:** `robots.txt` (с явным разрешением ИИ-краулеров и `Clean-param` для Яндекса),
  `sitemap.xml` (генерируется из сборки: `npm run sitemap`), Schema.org (Article + FAQPage +
  BreadcrumbList в статьях; Organization + WebSite на главной; на страницах услуг, кейсов и
  посадочных `ai-agenty`/`avtomatizaciya-prodazh`/`ii-assistent-dlya-sajta` — BreadcrumbList),
  `.htaccess`, canonical на всех страницах.
- **Проверки:** `npm run check` = сборка → сверка с `legacy/version-4` → sitemap актуален →
  JS на всех страницах → интерактив kit → SEO-аудит (`npm run audit`). То же гоняется в GitHub Actions.
- **Деплой:** Vercel (preview `ss-ai-preview.vercel.app`) → Beget (prod, rsync `site/dist/`).
- **Графика:** SVG-фигуры рисуются вручную в статьях (2–3 шт/статья, данные из текста).
- **CSS-токены:** переменные в `:root` (цвета, шрифты, отступы), бан-лист идей в голове (нет cyan/purple, нет эмодзи, нет курсива).

### Блог: правила
- Статья = H1, лид, 10–12 H2, FAQ×5, TL;DR, 2–3 SVG-фигуры, CTA.
- Автор: «Олег Кречетов, основатель Smart Solutions» + Schema Person.
- Schema: Article + FAQPage + BreadcrumbList (в статьях нового образца строится из данных `Article.astro`).
- Статьи нового образца — макет `src/layouts/Article.astro` + библиотека `src/components/blog/` и
  `public/blog-assets/kit.{css,js}`; эталон — `blog/ii-dlya-yuristov.astro`. С 2026-10-05 на макет
  `Article.astro` переведены все 21 статья; `Base.astro` остаётся каркасом для не-статейных страниц.
- Запреты в тексте: «революция», «магия», «просто посадить», неподтверждённые цифры без пометки «оценка/пример».
- **Стоимость часа сотрудника — одна формула на весь сайт:** полные затраты на сотрудника за месяц ÷ 168
  (21 день × 8 часов). Никаких «÷150 × 1,5», «÷160», «÷173», «÷176». Примеры: 80 000 ₽ → 476 ₽/ч,
  100 000 ₽ → 595 ₽/ч, 120 000 ₽ → 714 ₽/ч, 160 000 ₽ → 952 ₽/ч.
- **Калькулятор статьи:** умолчания ползунков берутся из примера этой же статьи, а в подписи
  (`note`) пишется, откуда цифры и что в расчёт не входит. Иначе читатель видит две разные арифметики.

## 4. Workflow сессий

### В начале каждой сессии
1. Прочитать этот `CLAUDE.md`.
2. Прочитать `SESSION.md` — он короткий (только текущий месяц). Историю брать из
   `git log --oneline -40`: сообщения коммитов содержательнее пересказа. Старые выпуски журнала —
   в `deliverables/archive/SESSION-2026-06-09.md`, их читать не надо.
3. `MODEL-ROUTING.md` — какая модель на какую задачу.
4. Проверить `git status` и текущую ветку. **Если статус не пустой — сначала
   `git fetch -q origin <ветка>` и `git reset --mixed FETCH_HEAD`, и только потом что-то коммитить.**
   Среда периодически сбрасывает локальный HEAD на базовый коммит, а в `.git/config` появляется
   `core.sparseCheckout = true` без файла шаблонов — тогда git показывает сотни фантомных удалений,
   и `git add -A` закоммитил бы их. Подробности — в `SESSION.md`, раздел «Известные грабли».
5. Убедиться, что работаем в `site/`.

### Как ведём задачи (договорённость 2026-09-25, уточнена 2026-10-05)
1. **Большая задача** — новая статья, новая посадочная, редизайн раздела: командой ролей,
   состав от 10 ролей, обязательны критики (читатель, скептик, эксперт предметной области)
   и отдельный проверяющий. Отчёт — `deliverables/TEAM-RUN-*.md`; результат команды,
   а не пересказ процесса.
2. **Точечная задача** — правка цифры или формулировки, перенос статьи на макет, вычитка:
   напрямую, без разыгрывания ролей и без отчёта. Варианты и выбор показываем в чате.
3. В обоих режимах фиксируем, что сделано и чем проверено.
4. Ничего не публикуем, пока `npm run check` в `site/` не зелёный.
5. `audit-layout` в работе гоняем по изменённым страницам (`--only`, ~20 с на страницу).
   Полный прогон — 31 страница × 4 разрешения, ~7 минут — только перед деплоем.

### Во время работы
1. После каждого значимого шага обновлять `SESSION.md` (append, не overwrite).
2. Перед коммитом проверять, что изменения затрагивают только нужные файлы.
3. **Не коммитить `.claude/`, `.DS_Store`, `.vercel/`, `node_modules/`, `dist/`** — `site/.gitignore` настроен.
   `dist/` собирается заново, артефакты сборки в git не нужны.
4. Коммиты — conventional commits: `feat:`, `fix:`, `content:`, `style:`, `seo:`, `deploy:`, `docs:`, `chore:`.

### В конце сессии
1. Обновить `SESSION.md`: что сделано, что не доделано, следующие шаги.
2. Если были открытия — сохранить их в `SESSION.md` (у `MODEL-ROUTING.md` см. п. 4.1) или в skills.
3. Прогнать `npm run check` в `site/` — сборка и все проверки должны быть зелёными.
